## 1. 문제

평면 레이아웃에서도 overlay와 check 로더가 재귀 탐색·간접 호출을 사용한다.
`modules/language.home.nix`에는 패키지 설치에 쓰이지 않는 메타데이터가 남아 있다.
구성을 읽는 사람이 어떤 파일이 실제 출력에 포함되는지 여러 로더를 따라가야 한다.

## 2. 해결 방향

출력의 공개 이름과 동작을 유지하면서 평면 디렉터리는 평면으로 읽고, 소수의
overlay와 check는 명시적으로 연결한다. 언어 패키지 데이터는 소비하는 값만 둔다.
코드 복잡도의 BEFORE/AFTER를 같은 기준으로 측정한다.

## 3. 사용자 스토리

1. 설정 관리자로서 `flake.nix`에서 overlay 순서와 check 구성을 바로 확인하고 싶다.
2. 설정 관리자로서 잘못된 overlay 입력이 조용히 누락되지 않기를 원한다.
3. 기존 사용자로서 Home Manager 출력 이름, 사용자와 홈 경로, 설치 패키지가 유지되기를 원한다.

## 4. 요구사항

- R1. overlay 순서는 Rust, 기존 9개 로컬 overlay의 사전순, pinned Neovim으로 유지한다.
- R2. `guard-tests`, `formatting`, `home-activations` check 이름과 guard 결과는 유지한다.
- R3. Home Manager 출력 27개와 대표 alias의 사용자·홈 경로는 유지한다.
- R4. 평면 `modules/`의 `.home.nix`와 `.nixos.nix` 발견 결과를 유지한다.
  하위 디렉터리가 생기면 조용히 무시하지 않고 실패한다.
- R5. `language.home.nix`의 설치 패키지 순서를 유지하고 미사용 메타데이터를 제거한다.
- R6. 동일한 7개 코드 파일 범위에서 물리 줄 수와 비어 있지 않은 비주석 줄 수를
  전후 측정한다. 후자는 최소 20% 줄이는 것을 목표로 한다. 런타임 성능 개선은 주장하지 않는다.
- R7. 기존 guard, Bats, lint 및 대표 flake 출력 평가가 통과한다. 시스템·홈 활성화는 하지 않는다.

## 5. 범위 밖

공개 출력 이름 정리, 플랫폼별 모듈 통합, 키맵 변환기 통합, 패키지 버전·핀·lockfile
수정, NixOS Podman 설정 수정, 배포·적용.
